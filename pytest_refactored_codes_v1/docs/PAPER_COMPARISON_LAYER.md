# Paper-Comparison Layer — Architecture & How-To

> The layer that answers: *"After a model edit, do my DATA1/DATA2 outputs still match the published paper?"*
>
> Spec: [`PAPER_COMPARISON_PROMPT.md`](./PAPER_COMPARISON_PROMPT.md)
> Test files: [`tests/test_data1_paper_comparison.py`](../tests/test_data1_paper_comparison.py), [`tests/test_data2_paper_comparison.py`](../tests/test_data2_paper_comparison.py)
> Helper: [`helpers/paper_comparison.py`](../helpers/paper_comparison.py)

---

## 1. Why this layer exists

The suite's four base layers (smoke / artifact / validation-gate / structural-regression) all catch
SHAPE changes — a Var deleted, a Constraint added, a registry shrunk. None of
them catch the case where the model preserves its structure but the numeric
outputs shift. That's the kind of change a diffusivity-coefficient edit
produces: the Sherwood mass-transfer correlation (Ouimet et al. 2022, Eq. 4)
gets a new D term, no new Pyomo Var or Constraint is added, but every fitted
trajectory moves a little.

This is the layer that catches that.

## 2. How it works (one sentence)

For each row of `simulation_validation_manifest.csv` (56 rows across DATA1 + DATA2),
load the committed baseline CSV, load the corresponding produced artifact in
`paper_artifacts/data{1,2}/notebook_figures/`, compute the metric named in the
manifest, assert it is within tolerance, and write a drift report.

## 3. The three sub-layers (and when each runs)

| Sub-layer | Marker | Solver runs? | When you'd use it |
|---|---|---|---|
| **Smoke** | `smoke` | No | "Are my baseline CSVs even on disk?" — runs on every commit |
| **Mapping audit** | `regression` | No | "Does the refactor still produce every PNG named in the locked mapping?" — catches renames + dropped outputs |
| **Numeric regression** | `regression + nightly` | YES (one fixture per family) | "I just made a model edit, did the numbers move?" — the real answer to diffusivity drift |

### A gap we found during build, and how we handled it

The refactored pipeline writes 155 PNGs but only 1 companion CSV in
`paper_artifacts/data1/notebook_figures/`. The baseline CSVs in
`simulation_validation_data_files/` were generated by the LEGACY MATLAB stack —
they're per-figure long-format time series.

This means *CSV-on-CSV comparison without a solver run* is not possible for
most figures. The mapping-audit sub-layer adapts: instead of comparing
numerical values, it asserts that every `target_id` in the locked mapping
resolves to a PNG that exists on disk. That catches the "refactor renamed an
output" and "refactor stopped producing this figure" cases, which are the
two most common silent failures.

The **numeric** answer to "did my diffusivity edit change DATA1/DATA2" requires
running the refactored pipeline forward simulation, extracting the data that
would have been plotted, and comparing to the baseline CSV in memory. That's
the **Numeric regression** sub-layer, marked `nightly` because it touches the
solver. It's stubbed in v1 with a clear `pytest.skip` and a `TODO` pointing
back to this section.

The clean long-term fix is to add CSV-companion-emission to the refactored
library so the light sub-layer can do CSV-on-CSV comparison without a solver
run. That's a small library edit (one line per figure) and is documented as
a follow-up in `PAPER_COMPARISON_PROMPT.md` § Non-goals (it's out of scope for
the pytest suite itself).

## 5. The two locked authorities (sources of truth)

Both live OUTSIDE this folder and are read-only:

### `UnifiedFramework/DATA3/docs/validation/target_notebook_source_map.csv` (33 rows)

The locked mapping `target_id` → paper item → exact filename in the refactored output.
Example row (DATA1):

```
D1-M-F2  Fig. 2 (all four plots)  Figure set  DATA1
  artifacts: mass-dat501.1.png; concentration-dat501.1.png;
             mass-dat511.12.png; concentration-dat511.12.png
```

We do not edit this. If a refactor renames an output filename, fix the refactor
or update this CSV in one explicit commit.

### `UnifiedFramework/DATA3/docs/validation/simulation_validation_data_files/simulation_validation_manifest.csv` (56 rows)

The per-figure numeric oracle:

```
paper,figure_id,panel_id,artifact_kind,source_label,relative_csv,notes
DATA1,Fig. 2,A,timeseries,...,data1_main/fig2/data1_main_fig2_a.csv,Dataset 501.1
DATA1,Fig. 2,B,timeseries,...,data1_main/fig2/data1_main_fig2_b.csv,Dataset 501.1
...
DATA2,Fig. 6,curve_metrics,...,data2_main/fig6/data2_main_fig6_curve_metrics.csv,...
```

`relative_csv` resolves under `simulation_validation_data_files/` to the
committed baseline CSV.

## 6. Metric selection (per `artifact_kind`)

| `artifact_kind` | Metric | Default tolerance |
|---|---|---|
| `timeseries` | NRMSE between time-aligned series | 1% |
| `scatter` | MAE on points | 1% |
| `contour_grid` | max absolute relative diff over the grid | 2% |
| `table` | cell-by-cell relative diff | 1% |

Override per target in `baselines/paper_comparison_tolerances.csv`:

```
target_id,metric,tolerance,reason
D1-M-F4_A_mass,nrmse,0.02,sigma-sensitivity sweep has known numerical fuzz
D2-M-F3_A,mae,0.005,tight check; calibration-critical
```

## 7. How to run

```bash
# Smoke (every commit; < 2 s):
MPLCONFIGDIR=/tmp/mplconfig pytest -q -m smoke \
    pytest_refactored_codes_v1/tests/test_data1_paper_comparison.py \
    pytest_refactored_codes_v1/tests/test_data2_paper_comparison.py

# Light regression (primary use case — after a model edit; < 30 s if outputs exist):
MPLCONFIGDIR=/tmp/mplconfig pytest -q -m "regression and not nightly" \
    pytest_refactored_codes_v1/tests/test_data1_paper_comparison.py \
    pytest_refactored_codes_v1/tests/test_data2_paper_comparison.py

# Full regression (runs materialize_all; ~10 min per family):
MPLCONFIGDIR=/tmp/mplconfig pytest -q -m nightly \
    pytest_refactored_codes_v1/tests/test_data1_paper_comparison.py \
    pytest_refactored_codes_v1/tests/test_data2_paper_comparison.py
```

After every run, inspect the drift report:

```bash
ls -t pytest_refactored_codes_v1/_runs/run-*/paper_comparison_report.csv | head -1 | xargs cat
```

## 8. The diffusivity-edit workflow (your specific use case today)

1. **Before the edit** — capture a baseline of the current state:
   ```bash
   # Already happened — paper_artifacts/data{1,2}/notebook_figures/ exists
   # No action needed. Optionally, snapshot it:
   tar czf _runs/pre_diffusivity_outputs.tar.gz UnifiedFramework/DATA3/results/paper_artifacts/data1/notebook_figures/ UnifiedFramework/DATA3/results/paper_artifacts/data2/notebook_figures/
   ```

2. **Make the diffusivity edit** in `refactored_codes_v1/refactored_ucb_library.py`.

3. **Re-run** the DATA1 + DATA2 pipelines manually via the runfile.

4. **Run the comparison tests** (light regression sub-layer — no solver):
   ```bash
   MPLCONFIGDIR=/tmp/mplconfig pytest -q -m "regression and not nightly" \
       pytest_refactored_codes_v1/tests/test_data1_paper_comparison.py \
       pytest_refactored_codes_v1/tests/test_data2_paper_comparison.py
   ```

5. **Read the drift report**:
   ```bash
   cat $(ls -t pytest_refactored_codes_v1/_runs/run-*/paper_comparison_report.csv | head -1)
   ```

   Every row with `verdict=FAIL` names a figure that moved AND quantifies the
   move. Rows with `verdict=PASS` are unchanged.

6. **Decide**:
   - All `PASS` → diffusivity edit was structurally neutral for DATA1/DATA2. Ship.
   - Some `FAIL` with small drift → expected (diffusivity should affect cF more than mass).
     Check the affected figures match physical intuition. If yes, refresh baselines.
   - `FAIL` with large drift → bug in the edit. Revert + investigate.

## 9. How to add a new comparison case

The locked mapping is the authority. To compare against a new paper figure:

1. Add a row to `UnifiedFramework/DATA3/docs/validation/target_notebook_source_map.csv`:
   ```
   D1-M-NEW,Fig. NEW (some panel),Figure,DATA1,...,new_artifact.png,HIGH,...
   ```

2. Add the numeric baseline CSV under
   `UnifiedFramework/DATA3/docs/validation/simulation_validation_data_files/data1_main/figNEW/data1_main_figNEW.csv`
   and append a row to `simulation_validation_manifest.csv`.

3. The pytest discovers the new row automatically via parametrization — no
   test-code edit needed.

4. Optionally add a tolerance override to `baselines/paper_comparison_tolerances.csv`.

5. Commit the manifest update + the baseline CSV in the same PR.

## 10. How to refresh a baseline (when a deliberate physics change makes it real)

When you've deliberately changed the model and you want the NEW outputs to be
the baseline going forward:

```bash
# 1. Re-run the pipeline post-edit.
python refactored_codes_v1/refactored_ucb_runfile.py  # pick DATA1, DATA2

# 2. Copy the new produced artifact over the baseline (one figure at a time —
#    bulk-overwriting destroys the audit trail):
cp UnifiedFramework/DATA3/results/paper_artifacts/data1/notebook_figures/mass-dat501.1.csv \
   UnifiedFramework/DATA3/docs/validation/simulation_validation_data_files/data1_main/fig2/data1_main_fig2_a.csv

# 3. Commit BOTH the model edit AND the baseline refresh in the same PR, with a
#    note explaining the physical justification.
```

The pytest layer is intentionally NOT a baseline refresher — that gate stays
manual so a model change can never silently "fix itself" by overwriting its
own oracle.

## 11. Failure modes & troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `SKIPPED: produced artifact not found` | You haven't run `materialize_all(campaign="DATA1")` since the edit | Run the runfile or use the `nightly` marker to trigger the cached fixture |
| `SKIPPED: baseline CSV not found` | `simulation_validation_data_files/` is missing or in a different commit | `git status` on `UnifiedFramework/DATA3/docs/validation/` |
| `FAIL: NRMSE 0.014 > tol 0.01` | Real numeric drift OR tolerance is too tight | Read the drift; decide. Bump tolerance only if the change is physically justified |
| `ERROR: schema mismatch — baseline has columns {…}, produced has {…}` | Refactor changed an output column name | Sync `target_notebook_source_map.csv` or fix the refactor |
| Test runs in `nightly` block forever | Cached fixture is genuinely running `materialize_all` | This is by design. Drop the marker if you only want the light sub-layer. |

## 12. Why no PDFs are read at test time

The pytest layer never opens a PDF. The PDFs in
`UnifiedFramework/DATA3/published_works/` are the **human-readable reference**;
the comparison oracle is the rasterized + manifested artifacts in
`pdf_extract/` and `simulation_validation_data_files/`. Reading PDFs would
introduce a dependency (PyMuPDF / pdfplumber) for zero added information.

The PDFs were used ONCE, during 2026-03-06, to populate `pdf_extract/` via a
manifested extraction script (`extraction_manifest.csv`). That artifact is now
frozen and the source PDFs are only re-consulted if a new figure is added to
the locked mapping.

## 13. Visual layer (deferred extension)

A visual comparison sub-layer (SSIM image similarity against `pdf_extract/data{1,2}_{main,si}/`)
is documented in `PAPER_COMPARISON_PROMPT.md` § "Scope decision" as option (b).
It would live in `tests/test_data{1,2}_paper_visual.py` and would NOT modify
this layer.

Reasons it's deferred to a follow-up:
- A diffusivity edit changes numbers, not plot style.
- SSIM adds a Pillow / scikit-image dependency.
- The data1_main folder has no figure crops, only full-page renders, so DATA1
  visual comparison would be page-level (less precise).

When you're ready, the prompt section on scope is the brief to start from.
